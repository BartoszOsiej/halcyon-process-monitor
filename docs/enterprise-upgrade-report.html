Level 1: Supply Chain Security

L1 ✅ Supply Chain Security Foundation

The supply chain is the #1 attack vector for modern software. Level 1 establishes automated gates that prevent malicious or vulnerable dependencies from entering the codebase, and ensures every release is traceable to its source.

  • ✓
    License Compliance (cargo-deny) — Automated license auditing blocks PRs introducing forbidden licenses. Allowlist: MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Unicode-DFS-2016, Zlib, 0BSD, Unicode-3.0, MPL-2.0.
  • ✓
    Advisory Audit (cargo-deny) — Checks all dependencies against the RustSec advisory database. Known vulnerabilities block the PR immediately.
  • ✓
    SBOM Generation (CycloneDX) — JSON and XML Software Bill of Materials generated for every build. Attached to release artifacts for downstream compliance.
  • ✓
    Secret Scanning (gitleaks) — Scans every commit for hardcoded secrets, API keys, tokens, and credentials. Full history scan on PRs.
  • ✓
    Dependency Review — Automated review of new/changed dependencies on PRs. Blocks high-severity vulnerabilities before merge.
  • ✓
    Security Policy (SECURITY.md) — Enterprise-grade VDP with CVSS-based SLAs, severity classification, response timeline, Hall of Fame, and compliance alignment.

Level 2: Build Provenance & Signing

L2 ✅ Build Provenance & Signing

Level 2 ensures every release artifact is cryptographically signed, attested, and accompanied by verifiable provenance. This eliminates build tampering and enables customers to verify artifact integrity before deployment.

  • ✓
    SLSA Level 2 Provenance — Generated by slsa-framework/slsa-github-generator. Proves the artifact was built by GitHub Actions from this repository's source code.
  • ✓
    Sigstore Cosign Keyless Signing — OIDC-based keyless signing via Fulcio/Rekor. No long-lived signing keys — identity bound to GitHub Actions OIDC token.
  • ✓
    GitHub Artifact Attestation — Native gh attestation write bundles tied to the repository's identity. Verifiable via gh attestation verify.
  • ✓
    SHA-256 + SHA-512 Checksums — Dual-hash checksum files for all release binaries (talus-tui, talus-web, talus-ebpf.o). Included in release assets.
  • ✓
    SBOM Signing — The CycloneDX SBOM itself is signed with Cosign, ensuring the dependency list cannot be tampered with post-generation.
  • ✓
    Automated Release Notes — Changelog generation from git log between tags, with verification instructions for checksums, Cosign signatures, and SLSA provenance.

Level 3: Security Hardening & Audit

L3 ✅ Security Hardening & Audit

Level 3 hardens the codebase against common vulnerability classes. Every unsafe block is documented, security headers protect the web interface, and the crate enforces strict code quality via compiler lints.

  • ✓
    SAFETY Documentation — #![warn(missing_docs)] crate-level lint enforces documentation. SAFETY comments on all unsafe blocks: geteuid, getuid, getpwuid_r, signal, kill, read_unaligned.
  • ✓
    Security Headers — SecurityHeadersLayer (tower middleware) injects CSP, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy, Permissions-Policy on every HTTP response.
  • ✓
    Unsafe Audit — Every unsafe block documented with rationale and safety invariant. Audit trail in code comments for security review.
  • ✓
    Clippy Strict Mode — 0 warnings with -D warnings. Fixed pre-existing unused variable warnings. Enforced on every CI run.
  • ✓
    Crate Documentation — Module-level doc comment on main.rs describing the agent's purpose, architecture, and security model.
  • ✓
    Function Documentation — Doc comments on Monitor::start, kill_process, spawn_reader, passwd_dir and other public/important functions.

Level 4: Testing & Quality Gates

L4 ✅ Testing & Quality Gates

Level 4 establishes comprehensive test coverage and quality gates. The test suite grew from 13 to 36 tests (177% increase), covering edge cases, property-like invariants, state transitions, and initial state verification.

  • ✓
    Test Count: 13 → 36 — 23 new tests added. 177% increase in test coverage across all modules.
  • ✓
    Edge Case Tests — extract_extension with 8 boundary cases, cstr_to_string with 5 variants (empty, null, valid, long, unicode).
  • ✓
    Entropy Tests — Uniform string (entropy ≈ 0), high entropy (> 0.5), single character. Validates the heuristic scoring engine.
  • ✓
    Monitor Invariants — Window eviction policy, threshold=0 disables alerts, auto-kill action triggers, orphan PID handling.
  • ✓
    Empty State Tests — top_files, extension_counts, rate_history, stats_sorted, flatten_tree all handle zero-data gracefully.
  • ✓
    Init State Tests — Uptime near zero, total_events=0, total_lost=0 at startup. Validates clean initialization.
  • ✓
    Clippy Zero Warnings — -D warnings enforced. Fixed 2 pre-existing unused variable warnings. Clean build on every CI run.
